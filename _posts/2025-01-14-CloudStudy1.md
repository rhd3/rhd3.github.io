# 1. 도커의 개요 및 설치
## 1.1 도커의 개요
### 1.1.1 도커란?
* 도커란?
도커(Docker)는 애플리케이션을 컨테이너라는 경량화된 가상 환경에 패키징하여 배포할 수 있게 해주는 플랫폼이다. 컨테이너는 애플리케이션과 그 실행에 필요한 모든 종속성을 포함하고 있다.    
* 도커 컨테이너의 특징
   * 모듈성
    > 전체 애플리케이션을 분해할 필요 없이 일부를 분해하고, 업데이트 또는 복구 가능
   * 계층 및 이미지 버전 제어
    > 각 도커 이미지 파일은 계층구조로 이루어짐
   * 롤백
    > 모든 이미지에는 계층이 있으며, 현재 이미지가 부적절한 경우 이전 버전으로 롤백 가능
   * 신속한 배포
  > 컨테이너를 활용해 필요한 이미지만 배포하기에 속도가 빠름
### 1.1.2 도커 구성요소(Docker Component)
* 도커 엔진(Docker Engine)
  * 도커 클라이언트(Docker Client):도커 명령줄 인터페이스(Docker CMD)
  > 도커 데몬(dockerd)에게 도커 API를 사용하여 명령을 보내는 프로세스로 둘 이상의 데몬과 통신할 수 있다.
  * 도커 데몬(Docker Daemon): 도커의 데몬(dockerd)
  > 도커 클라이언트에게 받은 Docker API 요청을 수신하고 처리하여 도커 객체를 관리하는 프로세스로, 도커 서비스를 관라하기 위해 다른 데몬과 통신할 수 있다.
* 도커 레지스트리(Docker Registry): Docker에서 실행되는 이미지를 저장하는 저장소
> 주로 Docker Hub(https://hub.docker.com) 라는 공식 저장소를 사용한다. 
* 도커 객체(Docker Object)
  * 컨테이너(Container): 애플리케이션과 그 의존성을 포함한 독립적인 실행 환경
  * 이미지(Image): 컨테이너를 생성하기 위한 설정을 하나로 합친 템플릿으로, 파일 시스템의 스냅샷    
 
   
### 1.2 도커의 기능
* Build: 도커 이미지를 만듦
 > 도커는 애플리케이션의 실행에 필요한 파일,설정 등을 모아 이미지를 생성한다. docker 명령을 사용해 이미지를 tar파일로 생성(수동)하거나, Dockerfile을 사용해생성(자동) 할 수 있다. 하나의 이미지에는 하나의 애플리케이션만 넣어 두고, 여러 개의 컨테이너를 조합하여 서비스를 구축하는 방법이 권장된다. CI/CD 관점에서 코드에 의한 인프라의 구성 관리를 생각하면 Dockerfile을 사용하여 관리하는 것이 바람직하다.
* Ship: 도커 이미지를 공유(ship/share)   
 > 도커 이미지는 도커 레지스트리(Docker Hub)를 이용해서 공유 할 수 있다. Docker Hub에서 Ubuntu, CentOS와 같은 Linux 배포판의 기본 기능을 제공하는 베이스 이미지를 배포하고 있고, 베이스 이미지에 미들웨어, 라이브러리, 애플리케이션 등을 넣은 이미지를 겹쳐서 독자적인 이미지를 만든다. 도커 레지스트리는 docker 명령을 사용해 로그인하고 이미지를 검색, 업로드, 다운로드 할 수 있는 공유 저장소이다. Github 또는 Bitbucket 등과 연계하여 사용할 수 있으며, Github 상에서 Dockerfile을 관리하고, 도커 이미지를 자동으로 생성할 수 있다. (Automated Build)   
* Run: 도커 컨테이너를 작동시킴   
 > 도커는 Linux 상에서 컨테이너 단위로 서버 기능을 작동시키고, 여러개의 컨테이너가 하나의 Linux 커널을 공유하고 있다. 컨테이너 안에서 작동하는 프로세스를 하나의 그룹으로 관리하며, 그룹마다 각각 파일 시스템이나 호스트명, 네트워크 등을 할당하여 그룹이 다르면 프로세스나 파일에 엑세스 할 수 없다. 독립적인 관리를 위해 Linux 커널의 기능인 namespace, cgroups등의 기능이 사용된다.
